# hawaii-diag - Moto E32 (XT2227-1, Unisoc T606) 4.14.199 kernel

Branch cut from the vendor OSS drop `R-11-release-RORS` @ `c4e610cd833c`
("Add design file") so that every local change lives in git instead of only in
the working tree.

Nothing on this branch is meant to ship.  It contains:

* build fixes needed to compile the OSS drop with clang 11 / ld.lld,
* the backports the RORS userspace expects (file refs, anon_vma counters,
  SIPC shared-memory copies, SPRD uapi ABI),
* **DIAG only** boot instrumentation: entry-stub hooks, framebuffer text
  console, point-in-time probes, AON watchdog arming, late KVM init.

## The DIAG code

Everything the instrumentation needs is in this repository:

    diag/prepare_stage_panics.py   generates include/linux/diag_stage.h and
                                   patches setup.c / printk.c / init/main.c /
                                   kernel/notifier.c (idempotent)
    diag/stage_build.sh            runs the generator and builds the Image

The generated header is committed as a snapshot, but the generator is the
source of truth: re-run it after changing it.

    cd ~/kernel-sprd
    ./diag/stage_build.sh <panic> <arm> <smc> <paint> <screen>

    panic   0..8   panic() at that stage (only resets from stage 8 onwards)
    arm     0..8|9 arm the AON watchdog there (9 = every stage >= 2)
    smc     0..8   PSCI SYSTEM_RESET at that stage
    paint   0..2   1 = one band per start_kernel() stage, 2 = setup_arch() probes
    screen  0|1    framebuffer text console (printk mirror + milestone line)

Output: `Image.p<panic>a<arm>s<smc>q<paint>c<screen>` in the tree root, plus
`include/linux/diag_stage.h` and `include/linux/diag_font.h` generated by
`diag/prepare_stage_panics.py`.

Toolchain: `~/toolchains/clang+llvm-11.0.1-x86_64-linux-gnu-ubuntu-20.10/bin`
(the script exports it).  `.config.diagwdt` is the working config; KCFLAGS
carries the `DIAG_*` defines for `.c` files.  **KCFLAGS does not reach `.S`
files**, so the `head.S` probes are unconditional.

## State at 2026-11-01 (late evening)

The custom kernel **does boot into the idle loop** - it is not stuck in
`setup_arch()` any more.  The panel shows a real backtrace from the CPU_PM
notifier chain:

    atomic_notifier_call_chain+0x48/0x150
    cpu_pm_exit+0x2c/0x54
    arm_enter_idle_state+0x30/0x50
    cpuidle_enter_state+0x218/0x310
    do_idle...
    cpu_startup_entry...
    kernel_init...
    start_kernel...

That is `CONFIG_DEBUG_NOTIFIERS` rejecting a notifier callback that is not in
core kernel text (`core_kernel_text()` stops accepting `.init.text` once
`system_state == SYSTEM_RUNNING`).  The stock `WARN(1, "Invalid notifier
called!")` fires at **every** cpuidle exit, so it buried the real log tail
under an identical backtrace.  Commit 8 replaces it with a one-time report
that names the block and the callback.

Two bugs of the instrumentation itself were found the same way and fixed in
commit 8:

* the console state was file-scope static, so every translation unit that
  includes `diag_stage.h` had its own copy - `init/main.c`'s stage tags and
  `printk.c`'s mirror both looked at a `diag_scr_ready` that nothing ever
  set, and drew nothing.  There is now one `struct diag_console diag_state`,
  defined in `arch/arm64/kernel/setup.c`.
* rows 1..3 are permanent: they carry the EL2 report (`__boot_cpu_mode`,
  `is_hyp_mode_available()`, `ID_AA64PFR0_EL1`, MIDR), which is the fact KVM
  on arm64 depends on, so it survives the log scrolling past it.

Still open: **userspace never comes up**.  The kernel reaches the idle loop,
`adb` never appears, and the display never leaves our console, so `init` is
stuck somewhere after `setup_arch()`.  The stage tags 22..28 (init/main.c
stages 2..8) now draw on the milestone line and will say how far
`kernel_init()` got.
